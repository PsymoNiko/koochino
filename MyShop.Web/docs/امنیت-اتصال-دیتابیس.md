# امنیت رشته اتصال (Connection String) و پسورد دیتابیس

## چرا پسورد را هش نمی‌کنیم؟

- **هش (Hash)** یک‌طرفه است؛ از روی هش نمی‌شود پسورد اصلی را به دست آورد.
- برای اتصال به SQL Server باید **پسورد واقعی** به سرور فرستاده شود، بنابراین استفاده از هش برای خود connection string ممکن نیست.
- راه‌حل امن: **پسورد و connection string را در کد یا مخزن نگه ندارید** و آن‌ها را از محیط امن (User Secrets، متغیر محیطی، یا سرویس مخفی) بخوانید.

---

## اقدام‌های پیشنهادی

### ۱. محیط توسعه (روی سیستم خودتان)

از **User Secrets** استفاده کنید تا connection string و پسورد داخل فایل‌های commit‌شده نباشند.

پروژه شما از قبل `UserSecretsId` دارد. در پوشه پروژه (MyShop.Web) اجرا کنید:

```bash
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "Server=آی‌پی,پورت;Database=koch;User Id=koch;Password=پسوردواقعی;TrustServerCertificate=True;MultipleActiveResultSets=True;"
```

بعد از این کار، مقدار از **appsettings.json** override می‌شود و در اجرا از User Secrets خوانده می‌شود.

- **مزیت:** connection string و پسورد داخل repo و فایل‌های پروژه نیست.
- **نکته:** در `appsettings.json` می‌توانید مقدار واقعی را حذف کنید و فقط یک مقدار placeholder بگذارید (یا اصلاً نگذارید و فقط از User Secrets استفاده کنید).

### ۲. محیط تولید (سرور)

روی سرور **هرگز** پسورد را در appsettings.json نگذارید. از یکی از این روش‌ها استفاده کنید:

- **متغیر محیطی (Environment Variable)**  
  نام کلید در ASP.NET Core به این شکل است:
  - `ConnectionStrings__DefaultConnection` (دو خط تیره `__`)
  - مقدار = همان رشته اتصال کامل شامل پسورد.

  مثال در ویندوز (PowerShell یک‌بار قبل از اجرای برنامه):
  ```powershell
  $env:ConnectionStrings__DefaultConnection = "Server=...;Database=koch;User Id=koch;Password=پسورد;..."
  ```
  یا در IIS: در Application Pool → Advanced Settings → Environment Variables اضافه کنید.

- **Azure Key Vault / سرویس مخفی دیگر**  
  در صورت استفاده، connection string را آنجا ذخیره کنید و در برنامه از `IConfiguration` یا Azure Key Vault Provider بخوانید.

### ۳. حذف پسورد از مخزن (Git)

- در **appsettings.json** (و هر فایلی که commit می‌شود) connection string واقعی با پسورد را **حذف** کنید.
- یک فایل **appsettings.Template.json** یا **appsettings.Example.json** با مقدار placeholder (بدون پسورد واقعی) در مخزن نگه دارید تا بقیه بدانند ساختار چیست.
- در **.gitignore** در صورت نیاز فایلی مثل `appsettings.Local.json` را اضافه کنید تا تنظیمات محلی شما commit نشود.

---

## خلاصه

| هدف | کار مناسب |
|-----|------------|
| پسورد هش شود و در connection استفاده شود | ممکن نیست (SQL به پسورد واقعی نیاز دارد). |
| پسورد در فایل و مخزن نباشد | User Secrets (توسعه) + متغیر محیطی یا Key Vault (تولید). |
| فقط روی یک ماشین پسورد باشد | User Secrets یا فایل محلی که در .gitignore است. |

با این روش‌ها پسورد «هش» نمی‌شود، اما از نظر امنیتی به‌صورت امن (خارج از مخزن و فایل‌های عمومی) نگهداری می‌شود.
